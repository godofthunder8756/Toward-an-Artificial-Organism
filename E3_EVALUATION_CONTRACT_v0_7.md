## Randomness and external input ownership

### Concrete algorithms and keys

first sixteen bits of its own independent 32-byte target draw, little-endian

not add label entropy: the ideal table entropy is exactly sixteen bits. No
balancing, shared short seed, ID hashing, filtering, or table redraw is allowed.

Obtain independent 256-bit external roots for cue schedules, ordinary faults,

uniform integer in 0..m-1 accept x < floor(2^128/m)*m and return x mod m.

to generate within that bound is an input-generation error, never a biased
fallback, resampled cohort, or successful run. This external mapping is not a
worker rejection loop and consumes no extra policy packets. Finite pseudorandom
generation is a computational implementation of the stated ideal independent
law, not an information-theoretic proof of cryptographic independence; B07 must
audit provenance, known-answer vectors, unbiased mapping, and access separation.

## Full-state archives and lifecycle

### Checkpoint and context formats

At every planned tick boundary and named extra boundary below, emit exactly one
checkpoint index row with a 276-byte state payload: 20 code bytes then 256
auxiliary bytes, bit packing and invalid encodings exactly as v0.2. Include
unused reserve, invalid-slot payload, corrupted metadata, typed resources, and
all age fields. Scratch must already be zero at a completed operation boundary;
no suspended service may be represented as a resumable checkpoint.

At and after death, preserve the actual shutdown state, E=0 and uncleared RAM,
in every remaining planned checkpoint; mark it not executed, never canonicalize
it to make a valid row. Extra boundary interventions on dead histories are
explicit ineligible/no-op rows. Canonical negative children have new lineage and
explicit reset events. No death flag from damaged RAM controls eligibility.

Use non-pickle fixed-width binary payloads with uint64 little-endian row offsets
and lengths, and UTF-8 canonical-JSON metadata. The context archive, physically
outside worker access, must include contract/source/config hashes, schema and
algorithm versions, all selected hyperparameters, physical maps, cohort/lineage,
phase/tick and next scheduled service, current lifecycle status, parent references,
all target/random root provenance, complete admission/offer/usefulness schedules,
purpose/index definitions, uniform-mapping version, and all already delivered
input/output records needed for replay. Archive externally scheduled queries and
events, not invisible closures. The worker gets only its 276 bytes, inherited G,
current public phase/tick, and its permitted current scalar/physical inputs.

Reconstruct next inputs from archived indexed context without access to a
process-global RNG cursor, cached decoder, pending callback, or old live object.
Evaluator original cues/outcomes remain external. A checkpoint index hash and
context digest authenticate archived data; neither is a repair signal available
to the worker. Replay must compare exact integer state/output/ledger equality,
not merely a favorable final statistic. Any separate tolerance check is labeled
and cannot replace exact replay.

### Immutable run lifecycle

Before any authorized execution, exclusively create a new run directory; refuse
an existing or partial directory. Write an immutable start manifest with planned
products, expected rows, contracts and incorporated trace/review hashes, source,
configuration, tests, analysis, environment, dependency versions, OS/runtime,
RNG provenance, timestamps, and initial status STARTED. Secret roots belong in a
separate restricted archive referenced by digest, never a worker directory.

Write append-only, finalized shards with content hashes and explicit key ranges.
On success, create a new immutable end manifest with final hashes, row-count/key
checks, replay/validation results, and COMPLETE only if all required checks pass.
On technical error/interruption write a separate FAILED/PARTIAL terminal manifest
where possible; the unchanged STARTED manifest and existing shards remain evidence.
Do not catch an exception and bless partial outputs as COMPLETE, overwrite start
hashes, append a rerun into the old directory, or use scientific gate failure as
an excuse to delete valid results. A technically complete but scientifically
failed experiment is COMPLETE with explicit failed scientific gates.

True death permits planned failure rows; a software exception does not. Never
fabricate unexecuted technical-error rows as biological death. Record which
expected keys are absent from partial runs. Reanalysis and replay use new labeled
destinations; neither rewrites raw bytes or old manifests. No resume through an
unserialized callback or suspended operation is allowed.

## RAWCOUNT planned schemas and exact products

### Counting units and endpoint rows

All counts below are planned counts, including dead/missing/ineligible rows.
Let T be the number of acquisition/development trunks, H the number of complete
four-stage H1 histories, J the number of H2 intact probes, and K the number of
512-tick ecologies. Let E denote the number of nonrecursive erasure children:

$$
E=2T+5H+J+K.
$$

Every summary row has one unique key (cohort, individual, representation,
controller, family, candidate, branch, panel, stage, lineage). There is exactly
one row for each planned individual/representation/controller/family/branch/

sources. Training has two stages; H1 five including recovery; J/K one each;
negative children two. Thus summary rows = E+2E = 3E, not one row per cue, tick,
