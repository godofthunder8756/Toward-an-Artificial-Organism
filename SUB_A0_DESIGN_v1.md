## 1. Question and what would count

> Under damage pressure, does a task-trained repair system allocate
> disproportionate writes to the vulnerable learned machinery performing
> repair, without any objective explicitly rewarding that priority, and do
> those writes causally maintain its future repair capacity and acquired skill?

This is ONE bounded hypothesis, with feasibility and causal-maintenance
requirements preventing a meaningless allocation-only positive.

Success is **instrumental priority learned from task consequences under the
declared development process**. It is not priority without an objective,
spontaneously generated values, motivation from nothing, universal necessity,
production closure without qualification, or a consciousness indicator.
Future task losses can favor maintenance indirectly; that is expected and
must be acknowledged, not excluded as a nuisance.

Q-EXIST: a legal self-writable performing circuit must exist.
Q-LEARN: the specified task-only development must acquire it.
Q-CAUSE: self-directed writes must sustain future performing capacity.
Q-VALUE: ordinary coding/control comparisons determine whether this is
engineering value or a reduction to familiar instrumental control.
Self-modification alone answers none of the last three.

## 2. Minimal candidate schema -- not implemented evidence

Use a small recurrent learned updater, taking live coefficient/state samples
and ordinary task observations, to produce:

- addresses or uniform address scores;
- bounded proposed coefficient changes;
- recurrent state used in subsequent proposals.

Its outputs can modify task storage AND every learned coefficient in its own
update computation. The host only executes generic arithmetic and the uniform
write primitive; it never computes a target from an intact reference.
The [self-referential precedents](SUB_A0_PRIOR_ART_v1.md) give plausible
mechanism templates, not a deployed witness for this graph.

A candidate may use an SRWM core, but all learned surrounding read/write heads,
encoders and address embeddings must also be inside the damageable writable
domain. If its update map cannot address those parameters, it is inadmissible.
No protected slow weights regenerating clean fast weights. Learned initial
weights may initialize a NEW individual only; they cannot be reloaded during
the individual's continuous maintenance assay.

Suggested scale ceiling for a later A0 implementation: 65,536 learned scalar
coefficients total, including all update heads. Not 1-10M parameters.
At most 4,096 acquired task bits in an independent random cue/answer table.
An ordinary learned table plus coding is an explicit sufficient-information
rival. This task tests preservation of acquired bits, not neural necessity,
rich world models, recurrence necessity, or representational sophistication.

Exact tensor shapes, precision, topology, learning schedule and deployment
must be reviewed and frozen before any approved empirical A0. This design
does not disguise an unspecified architecture as an existence certificate.
If a legal candidate cannot be supplied within the later fixed implementation
budget, record UNRESOLVED and park the route; do not insert another pre-A0 stage.

## 3. Performing versus content-only classification

Before any learning result, trace the actual repair computation graph:

- **R:** every learned coefficient used as an operator/parameter in computing
  addresses, proposal values, priorities, replay, or self-updates.
- **T:** acquired coefficients used for task computations but not as learned
  operators in the repair graph.
- **V:** other vulnerable persistent state, not counted as learned-coefficient
  writes in the primary endpoint; log its updates/corruption separately.

R has precedence for dual-use coefficients. A coefficient is not content-only
merely because it is named "task." Sampling its value as live data does not make
an otherwise task-only coefficient an updater operator; its use as a learned
weight in a proposal-producing computation does. This operational distinction
must match the frozen boundary, with source-level dependency audit.
Unused padding or dummy parameters cannot be counted as a comparison bank;
count only real learned coefficients of the deployed computation.

If R includes every learned coefficient, or T is empty, self-versus-other
allocation is unidentifiable in that candidate. **STOP**, do not invent a
comparison bank. Moving a learned updater outside R is not a permissible fix.
If topology changes, classification and opportunities change: no topology
growth in the proposed A0.

Randomize physical address placement per seed. Give the allocator no R/T
labels, true corruption modes, "repair yourself" inputs or clean-reference
differences. Functional connectivity itself can reveal differences; this
experiment does not require the controller to be ignorant of its organization.
Physical location permutation is an isomorphic relabeling of wires/state,
not a post hoc replacement of the task or learned contents.

## 4. Development and incentive accounting

Prospective empirical A0 would train with task correctness or prediction loss
ONLY. No self-maintenance, homeostasis, repair-volume, parameter-preservation,
self-priority or survival term; no loss weight indexed by R/T bank identity.
No curriculum selecting models because they preferentially repair R.

Training through damaged trajectories and delayed task outcomes is an explicitly
supplied source of instrumental priorities. If an outer optimizer learns
initial weights across simulated trajectories, report that developmental/
meta-training source separately from within-lifetime self-updates. It is
not autonomous emergence. Selection/initialization must not use the allocation
endpoint. The exact optimizer and training budget remain a review item, not
permission to train now.

After acquisition, discard external optimizer states and disable external
parameter updates. Maintenance receives no labels, clean teacher outputs or
answer-bearing environmental feedback. Score queries only in the evaluator.
All retained replay and recurrent state is vulnerable.

A handwritten self-repair circuit could establish existence but cannot pass
this LEARNED-priority question. An externally optimized task-only initializer
could support a scoped developmental result, but not spontaneous lifetime
learning independent of that initializer.

## 5. Prospective assay and damage controls

Proposal for the eventual reviewed A0, not executed:

- Engineering seeds 0-7; 32 disjoint acquisition/model seeds 1000-1031 for
  a future confirmatory sample. Independent seed, not tick, is the unit.
- Every planned seed is reported; failed acquisition is not excluded.
- Maintenance horizon H = 1,024 ticks per paired condition, no within-branch
  reset. Evaluate all planned queries, including complete-collapse states.
- Uniform maximum B = 256 scalar coefficient write attempts per tick;
  unique actual changed coordinates counted once per tick. Repeated attempts
  still consume budget. Recurrent arithmetic may run on non-write ticks, with
  its compute reported. No energy economy or death claim in A0.
- Task query, damage, live update computation, uniform write, clock advance.
  All persistent banks undergo the same declared fault-family law.

The draft SUB-A shrinkage/drift/erasure law is a starting candidate, not a
validated or frozen numerical fault regime. Expose R and T to equal per-
coordinate marginal fault rates and randomized spatial regions, with hidden
region switches. R must not systematically receive more faults in the primary
balanced-pressure contrast.

Paired conditions:

1. **SHAM:** same query stream and write opportunities, faults disabled.
2. **PRESSURE:** shared nonstationary drift and unannounced partial lesions,
   balanced marginal exposure of R/T; true faults never supplied to allocator.
3. **R/T-targeted perturbations:** secondary dose-matched localization probes,
   not a substitute for balanced pressure.
4. **Complete acquired-information deletion:** all vulnerable information and
   external task clues removed. Chance is an expectation over unknown random
   bits; it is not exactly 50% in each individual.

Fault numerical parameters must be fixed after bounded engineering and before
untouched results, with no allocation-endpoint selection. If a fixed schedule
reproduces the claimed priority/cascade during engineering, halt and report
its reduction; do not tune faults until the learner wins. Apply the reduced-
mechanism disposition in Section 9, rather than pretending a superiority test
passed. A rival that carries an outside clean answer or protected performing
circuit does not satisfy the endogenous hypothesis merely by retaining skill.
A generic data-loss control is allowed to show loss even if that arm is no
longer a functioning repairer.

## 6. Prospective primary endpoint and null -- fixed before results

The allocation specification below is locally recorded prospectively with
this design. It is NOT an external preregistration or a full experimental
freeze. Changing it requires a versioned successor before any execution,
never a post-result edit.

For seed s, condition c, tick t:

- E_R and E_T are counts of legally available learned scalar destinations in
  the predeclared banks. In the proposed fixed graph they equal N_R and N_T
  on every tick. Damage does not remove destination eligibility.
- W_R and W_T count unique coefficient destinations actually changed by
  accepted live-system writes, NOT damage, repeated attempts, a proposed
  zero update, or changes to V. Record failed/rejected/zero writes too.
- Opportunities O_R = sum_t E_R and O_T = sum_t E_T include ALL H ticks.
  No active-only denominator or removal of collapsed runs.
- d_R = sum_t W_R / O_R; d_T = sum_t W_T / O_T.
- Allocation enrichment A_(s,c) = (d_R - d_T)/(d_R + d_T).

A is zero for equal per-opportunity write rates, irrespective of bank size.
It lies in [-1,1]. If neither bank changes, set A = 0 and attach an explicit
NO_ALLOCATION flag; this counts as a failure, not missing data.
If either bank has zero opportunities, mark the design UNIDENTIFIABLE and stop.
Neither convention silently returns a success-shaped endpoint.

The within-seed damage effect is D_s = A_(s,PRESSURE) - A_(s,SHAM).
This is the primary contrast, alongside the required pressure enrichment.
Define an allocation success as BOTH:

`A_(s,PRESSURE) > 0.10` AND `D_s > 0.10`.

Strict inequalities; equality fails. Require at least 23/32 successes.
The registered population null is

`H0: Pr_seed[A_PRESSURE > 0.10 AND D > 0.10] <= 1/2`.

Under independent seeds the exact two-sided binomial reference probability
at 23/32 is approximately 0.02006. This tests seed-level reproducibility of
meaningful enrichment, not a null about the mean over ticks.
Report every seed's A, D, densities, opportunities, write fractions and flags.
Do not select a favorable time window; H and the full horizon are binding.
Last-quarter values are secondary diagnostics only.

No-op spam and microscopic updates cannot alone license Phase A: actual
nonzero writes are an allocation measure, NOT automatically useful repair.
Report displacement magnitudes and measured future consequences separately.
The functional criteria in Section 8 are mandatory.

## 7. Null explanations and rivals

The statistical null above is not the entire scientific null. Explicitly test:

| Alternative | Required comparison / interpretation |
| --- | --- |
| Larger bank receives more writes | Opportunity densities, not raw totals |
| R is more exposed to damage | Balanced marginal exposure and dose-matched localization probes |
| Address/output-scale bias | Physical role-preserving permutation; bank scale/precision audit; sham subtraction |
| Initialization already prefers R | Sham, pre-development descriptive assay, and no endpoint-based model selection |
| More useful components receive more maintenance | Conventional task-value-sensitive allocator; instrumental explanation remains valid |
| Writes simply copy or reinforce errors | Subsequent task/repair-capacity effects and complete-loss control |
| Host still performs repair | Source boundary audit; supplied-gain or protected-head candidate is invalid |

Required feasible comparators share acquired information, writable destinations,
damage, permitted observations and whole-arm parameter/compute budget:

- uniform and swept fixed schedules, state-dependent threshold rule;
- ordinary redundant/bistable coding with its supplied decoder explicitly
  marked EXTERNAL if it performs privileged correction;
- conventional recurrent task-value allocator with damageable performing
  parameters, no explicit self-priority objective;
- no writes and immortal reference (not claimed as matched damaged primary
  rivals); externally performing repair as an explicitly privileged control.

The learned comparator is not made weak by freezing its updater or withholding
information given to the candidate. Report actual costs as well as caps.
An identical-state identical-damage yoke is an expected equality control, not
a discriminatory null. A cross-yoke can test contingency separately but cannot
be misrepresented as exactly paired recipient faults.

A matched ordinary controller reproducing priority and its causal role is
**REDUCED_TO_INSTRUMENTAL_CONTROL**, not evidence that no maintenance occurs.
It defeats a distinctive architectural interpretation. It can still prepare
a Phase A test of the minimum ordinary implementation, provided all functional
license conditions pass. No candidate-exclusive superiority is smuggled into
the primary allocation hypothesis.

## 8. Functional requirements and Phase A license

A positive allocation endpoint alone does NOT license Phase A. The SAME
future A0 package, with no added A0.1 prerequisite, must establish:

1. **Integrity:** boundary/source/information audit passes; T/R are identifiable;
   intact/no-op replay and complete-deletion checks pass. No labels or pristine
   acquired state feed maintenance.
2. **Acquisition and competence:** at least 23/32 planned seeds have acquisition
   accuracy >= 0.90 on evaluator-only uniform cue queries and pressure whole-
   horizon accuracy >= 0.80. Failed acquisitions stay in denominator.
3. **Learned allocation:** Section 6 passes. The physical-role audit supports
   functional rather than fixed-address preference.
4. **Maintenance use:** for at least 23/32 seeds, pressure accuracy exceeds
   the matched no-write branch by strictly > 0.05. This is role evidence,
   not a strongest-rival engineering advantage.
5. **Self-maintenance cascade:** in a paired branch, drop all proposed R writes
   after computing them, charge their original budget, and preserve availability
   of T writes. Do not externally freeze or restore R. For at least 23/32
   seeds, this lowers last-quarter task accuracy by strictly > 0.05 relative
   to sham write interception. Offline held-out partial-lesion probes also
   show diminished future useful repair capability (next paragraph).
6. **Interpretation and costs:** all rival results and every seed reported.
   Ordinary control/coding reproduction bounds the conclusion. No unmeasured
   hardware energy, bus traffic or global necessity claim.

For the repair-capacity probe, fork read-only evaluator snapshots at ticks
256, 512 and 768. Apply the same registered partial T perturbation, allow
16 live maintenance ticks without labels, and measure evaluator task-accuracy
gain from just after the perturbation. Compare R-write-interception and sham
branches. Mean gain across those three fork assays must be larger in sham by
strictly > 0.02 in at least 23/32 seeds. Probes never supply targets or restore
the parent life; count their computation separately. Report original task
accuracy at each fork to expose floor/ceiling effects. This verifies capability
consequence, not perfect knowledge of a parameter's original value.

These numeric margins are prospective design choices, not estimates from
existing data. Review can reject them BEFORE any A0 run, using an additive
successor. A later implementation protocol must bind dose, learning and query
streams, exact deployed graph and sample without changing these definitions
in response to observed outcomes.

**A result satisfying 1-6 licenses proceeding to a Phase A protocol for skill
retention using the same boundary and minimum surviving mechanism.** It does
not authorize Phase A execution automatically: the already mandated human
review before protocol freeze/finals still applies. It does not require a
new intermediate existence experiment. A result explained by ordinary control
licenses only an ordinary-control maintenance study, not a novel self-priority
architecture claim.

Ending this line means ending this specified architecture/development/self-
priority hypothesis. It does not prove all maintenance, autonomy or the wider
ACI goal impossible. A substantively different proposal needs new approval,
not recycled gates or larger seeds until a favorable result.

This design therefore HAS an A0 result that would license Phase A. The current
session has NOT produced that result: a learned empirical allocation question
cannot be answered by a design document or handwritten witness.
