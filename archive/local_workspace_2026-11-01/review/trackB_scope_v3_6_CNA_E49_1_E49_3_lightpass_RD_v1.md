- **Modulo bias: no `%` reduction is used, but the method is not exactly uniform and is not rejection sampling (edit E-RD-6).** idx = ⌊(k + 1)·u⌋ with u = (w0 >> 11)·2⁻⁵³ maps 2⁵³ equally likely values onto k + 1 bins, so each index has probability within 2⁻⁵³ of 1/(k + 1). Exact counts do not depend on uniformity, and for an outcome-free assignment the bias is immaterial, but the text should say so rather than imply exact uniformity. **Float vs integer ambiguity:** the float product can round across an integer boundary. Exact demo: k + 1 = 3, a = (2⁵⁴ − 1)/3: float ⌊3·(a·2⁻⁵³)⌋ = 2, integer ⌊3a/2⁵³⌋ = 1. Implementations using the integer form would then disagree with the float form on such inputs. (For the example key, both forms agree on all 507 steps; checked.) **Edit:** pin the integer form idx = ((w0 >> 11)·(k + 1)) >> 53 and state the 2⁻⁵³ bound; or, if exact uniformity is wanted, specify Lemire-style rejection using w1–w3 of the same block as successive candidates with a declared deterministic fallback.
