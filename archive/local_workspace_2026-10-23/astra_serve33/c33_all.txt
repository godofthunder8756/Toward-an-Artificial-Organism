## 5. Ridge decoder: objective, lambda rule, intercept, zero variance, rank (Sec.7 blockers)

These rules are fixed before any inference, and are the same for every model, fold and tier.

**Objective.** On a fit set S, let w(h) = w(h)/Sigma_{h in S} w(h), which normalizes the weighted loss. Let Z be the features standardized with the fit-set w-weighted mean and the w-weighted population sd. The fit minimizes

J(b, beta) = Sigma_{h in S} w(h)*||q(h) - b - Z(h)beta||^2 + lambda||beta||^2_F,

where b  in  R^3 is an **unpenalized intercept**, so the solution has b = Sigma w q - (Sigma w Z)beta = Sigma w q. Eval-set features are transformed with the fit-set mean and sd only (fit-only standardization). The solution is computed by SVD of diag(sqrtw)*Z, so it is defined for any rank.

**lambda rule (stated in advance, nested within the fit set only).**
- Grid: Lambda = {10^-^6, 10^-^5, ..., 10^1}, 8 values. Lambda > 0, so ridge is unique under rank deficiency.
- Inner folds: each outer fit set (2 groups, 128 histories) is split into its **4 depth-5 prefix orbits**. Each depth-4 group splits into exactly 2 of the 8 depth-5 orbits.
- Selection: run leave-one-orbit-out over those 4 inner folds (inner fit sets of 96 histories). For each lambda, take the inner loss pooled over the 4 held-out orbits, weighted by w and divided by the fit-set mass. Choose the lambda with the smallest inner loss. Ties within 10^-^1^2 relative go to the **largest** lambda.
- Refit on the full outer fit set with the chosen lambda and score on Eval_f.
- No eval-set or outer information enters the choice of lambda. Selected lambda values are reported for every model and fold.
- Each model in a nested pair chooses its own lambda under the same rule.

**Zero-variance features.** A feature with fit-set w-weighted sd <= 10^-^1^2 (raw scale) is excluded from that fit, meaning its coefficient is 0. The exclusion is listed per model and fold. The same rule applies inside the inner folds.

**Rank and conditioning** (L177-L178).
- For every outer and inner fit, the report gives: the feature count after exclusion; the numerical rank of diag(sqrtw)*Z, with tolerance sigma_max*max(n,p)*eps_float64; the condition number sigma_max/sigma_min (inf if rank-deficient); and the effective conditioning sigma_max/sigma_rank.
- **Declared action if rank-deficient:** nothing changes. Ridge with lambda  in  Lambda is still defined, and no feature is dropped beyond the zero-variance rule. The fit is flagged RANK-DEFICIENT.
- Rank deficiency is not UNRESOLVED and not a failure. Effective sample size exceeding the parameter count is not taken as a guarantee of rank, conditioning or generalization. The old "> 10" support rationale is removed (L177).
- **Known in advance** (outcome-blind, Sec.12):
  - B_in+ is structurally rank-deficient in every outer fit set, because each orbit group fixes the group-invariant products r_0r_2 and r_1r_3 (readings indexed from 0). A two-group fit set therefore holds one of them constant (AB, CD, AC, BD) or ties them (AD, BC), and induces further exact collinearities among the readings and products.
  - In AB, CD, AC and BD: 1 zero-variance feature, leaving 35, with rank 28.
  - In AD and BC: 0 zero-variance features, 36 kept, rank 33.
  - Ridge then splits coefficients across collinear columns by minimum norm, and the held-out groups extrapolate that split. This is part of the declared analysis (Q4).

## 9. T (descriptive only, E32-5)

**Definition.** For a pair (P, Q) on identical inputs, let R(S->y) be the held-out R^2 of y  in  {e_P, e_Q}. It is pooled as in Sec.4, with denominator the fixed full-domain Var_w(y), and uses the Sec.5 decoder. The two brackets are:
- beta_P = R(S_P->e_P) - R(S_Q->e_P)
- beta_Q = R(S_Q->e_Q) - R(S_P->e_Q)

T = beta_P + beta_Q.

**What is reported.** beta_P, beta_Q, their sum, and the four underlying held-out losses, all separately. This is done for three feature types: STATE, CONF = [f, f(1-f)], and FQ = [f_S, q, f_S^2, q^2, f_S*q] per head.

**Astra's corrections (L63-L80; CNA erratum `4a5ad4f3...`).**
- T > 0 does **not** require both brackets to be positive. A positive sum is **not called a double dissociation** (L63).
- Carrying its own output does not guarantee T > 0 (L65).
- Exact own-target reconstruction by the complete output-plus-oracle control **does not make tau_fq a universal ceiling** on tau_state. T subtracts foreign-target performance, and held-out R^2 can be negative (L67-L69).
- The 2sqrts bound applies only to population projections. It is not a bound on these cross-validated, standardized ridge predictions (L80). It is not used.
- The sound reading (L73-L76): T is confounded by output accessibility and decoder geometry; a positive T cannot establish an additional error-assessment representation; and failing to exceed tau_fq would not establish absence of assessment.

**Pair rosters.** These are fixed descriptive rosters (L116-L121), reported separately by PR and arm and never pooled. Pairs that share checkpoints are not independent (E32-8).
- Within-seed, cross-arm pairs: 910 + 30 + 30 + 30 = 1000.
- Same-arm, cross-seed pairs: C(10,2) = 45 per arm x 23 arms = 1035.

- **Inference.** 290 x 256 histories x 8 steps = 593,920 GRU steps at about 816 flops each, plus 74,240 readouts at <= 1,540 flops. That is about 6*10^8 flops per implementation and about 1.2*10^9 flops for torch plus numpy. Time is ~1-12 s, plus ~6 s of model construction.
- **Primary.** 290 checkpoints x 4 models x 6 folds x 5 fits (4 inner + 1 outer) = 34,800 thin SVDs. Each SVD costs 4np^2, with n = 96 or 128 and p  in  {6, 14, 42, 50}. Per checkpoint and fold, the outer and inner fits together come to about 9.2*10^6 flops, so the total is about 1.6*10^1^0 flops: ~16-160 s, plus ~1 s of overhead.
- **Uniform-weight sensitivity** (230 TRAINED). About 1.27*10^1^0 flops: ~13-127 s.
- **T.** 230 own plus <= 4,070 cross decoders, giving <= 4,300 source-target combinations. Each runs 3 types x 6 folds x 5 fits, for <= 387,000 SVDs with p  in  {6, 8, 15}. That is about 1.7*10^1^0 flops: ~17-172 s, plus ~12 s of overhead.
- **Total.** About 1.1 min optimistic and about 8.2 min conservative, against the 50-minute cap. Each stage estimate is also under its own cap.
- **Memory.** The states and outputs are about 10 MB. With torch the total is under 0.5 GB.

## M1: the B_in+ baseline cannot be identified on the held-out groups (disclosure edit, extends Q4)
The rank deficiency is more than a conditioning footnote. Its effect on held-out prediction was measured from the bits only:

| folds | share of held-out centered B_in+ row norm outside the fit-set row space |
|---|---|
| AB, CD, AC, BD | 0.632 |
| AD, BC | 0.408 |

No linear decoder fit on the fit set can use those directions on held-out histories, whatever lambda is. For example, where r0r2 is fixed in the fit set, r0 and r2 are collinear there. The minimum-norm split of their coefficients then cancels on held-out histories, where the sign of r0r2 flips.

STATE is a nonlinear function of the history. It comes from predictors trained on source TRAIN histories, which E32-9 says are not held out from the predictor. So STATE can supply exactly those directions.

The consequence is that part of any C2 gain may come from the baseline's lack of identifiability under orbit holdout, not from hidden state carrying information the inputs lack.

The claim ceiling ("beyond the specified ... input baselines", "under the declared analysis") still holds. But Sec.5 and Sec.12 should state this as an outcome-blind pre-freeze disclosure, with the 0.632 and 0.408 figures. The report should not describe C2 as "beyond the information in the inputs".

Optional, for Astra: add, as a descriptive output, an input-only B_in+ -> q held-out loss per fold. This needs no checkpoint and would make the size of the baseline handicap visible. Whether to compute it before the freeze is Astra's call, because Sec.12 currently lists q-decoding as not yet computed.

## M2: the inner lambda folds are easier than the outer task (extends Q3)
Each depth-4 group contains 2 depth-5 orbits that share all of its depth-4 prefixes. For example, (p,0) and (p(+)5,1) fall in one orbit, while (p,1) and (p(+)5,0) fall in the other.

So the held-out orbit in each inner fold shares depth-4 prefixes with the inner fit set, whereas the outer folds share none. Inner validation therefore rewards less regularization than the outer task does.

This is outcome-blind and allowed, but the lambda rule is a mismatched proxy and should be described that way, not as tuned for the outer generalization. Astra should choose between:
- (a) keeping it as written, with that description;
- (b) the inherited fixed lambda = 10^-^3;
- (c) leave-one-depth-4-group-out inside the fit set. This mirrors the outer split, but it leaves only 64-history inner fits, where r0r2 and r1r3 are both constant.

I lean toward (b) as the primary, with (a) as a descriptive sensitivity. It removes one of the Delegate's own unanchored rules. This is not a blocker.
